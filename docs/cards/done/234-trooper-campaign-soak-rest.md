  - Stack: #0 ubwcoop+0xEADC3, #1 ubwcoop+0xB4F5A, #2 exe+0x5192B6A, #3 exe+0x503C6A6.
  - ubwcoop+0xEADC3 is the inlined wide-name copy loop of fname_text (mod/src/ue/reflect.cpp:117). It reads the name
    entry 16 bytes at a time; the entry at 0x150CFFE8 reports a wide name of at least 63 characters, so the read ran
    off the end of a mapped block into 0x150D0000.
  - ubwcoop+0xB4F5A returns into hit_queue (mod/src/ubw/hit_c132.cpp:144), just after the second hit_name_token call

  - The caller is detour_c132_gore_damage (hit_c132.cpp:208), which runs on every host for every gore damage event,
    with no env gate, so the play build has the same path.
  - So that event's FHitResult.BoneName held a value that is not a valid FName index. g_name_entry returned an address
    near the end of a name pool block, and fname_text copied past it. fname_text checks only for a null entry.
  - The crash event: in the fx log just before it, a BP_AI_Trooper_Morita_C (an AI trooper) shot a WarriorBug placed
    around (22492, 7700, 54). ADProjectile trail deactivations, then NS_FX_Gore_BloodHit_Red02 via exe+0x5192B6A, the
    same return address as frame #2. The 40 earlier "card132: host hit" lines on this map are all player hits with
    "hit bone None". So the event that crashed is a gore damage event from an AI trooper's projectile. That event
    type may not carry an FHitResult at +0x60, or it carries one that was never filled.
