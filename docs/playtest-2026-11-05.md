# Playtest 2026-11-05 (LAN/WAN, play build 7f734db36ab30611)

Bugs reported live by the user. Each becomes a card after the session.

1. **Client can't vault over a wall.** The game's mantle is a local move (assets: `AM_Arms_Mantle`, `MantleCurve`, `Shake_RegularMantle`). Likely cause to check: the client starts the mantle but the server copy never runs it, so the server snaps the pawn back (same shape as card 092/093 corrections). Symptom: nothing at all, no animation; the client bumps into the wall and does not get over. So the mantle never starts on the client (no snap-back). Likely the client's mantle trigger is gated or not running: check whether the mantle is a gameplay ability the client cannot activate (net execution policy, card 050-style ability gate), or a trace/check in the movement component that fails on the client's pawn.
2. **Client's shots play on the host as if the host fired.** When the client fires, the host hears the shot as its own (non-spatial, first-person sound) and gets the client's camera shake. Likely cause: the host's copy of the client pawn runs the full first-person fire cues (2D fire sound, camera shake) because the weapon or cue does not check that the shooter is locally controlled, or the mod's fire relay replays the shot through the host's own player path. Expected: the host hears a 3D sound at the client's position and gets no shake.
3. **Host gets the client's notifications.** The host's HUD shows the client's on-screen notifications. Probably the same root as item 2: code on the host's copy of the client pawn (or its controller/HUD lookup) treats it as the local player, e.g. HUD calls that resolve "player 0" instead of the pawn's own controller. Which notifications: TBD.
4. **Host's pause menu freezes the client.** When the host opens the pause menu (to go into settings), the client's game freezes too. Cause: the pause menu pauses the world (`SetGamePaused`/`SetPause`), and on a listen server that pauses the server, so every client stops. Fix direction: while a client is connected, opening the pause menu must not pause the world (block or skip the pause call in co-op; check what the client's own pause menu does too). Expected: the menu opens and the game keeps running on both machines.
5. **Tactical support flare lost when the client picks it up.** FED_C1M1 tactical support range: the client picked up the support flare. The client cannot use it (4 does nothing), and the host does not have it either, so the range is stuck. Card 058 completed the range only with the host taking the items. Likely causes: the pickup grants the support ability to the server copy of the client but the client's ability/input path (card 050/057 relay) does not cover support items, or the level script gives the flare to player 0 only and the client's pickup consumes it. Also check: does RESTART CHECKPOINT bring the flare back (workaround).
6. **Client can't see the host's bombing run.** The host called the tactical support bombing run (FED_C1M1 range); it did not show on the client's screen. Likely the strike actors (aircraft, bombs, explosions) spawn on the host only and are not replicated or relayed to the client (same shape as card 074 cosmetic grenade relay). Check whether the client still takes damage and whether bugs die on both screens.
7. **Client can't enter the capture-the-flag section: invisible wall.** The client is stopped by an invisible wall at the entrance to the capture-the-flag area of FED_C1M1; the host walks through. Likely cause: a blocking volume the level script turns off when the objective is reached. The script runs on the host only, so the host's copy is off, but the client's own copy of the placed blocker (placed actors are not replicated here, `bReplicates 0` like the pickups) stays on, and the client's own movement collides with it. Fix direction: relay the blocker's collision/enable change to the client (like card 056 PickupGone), or find the script call (`SetActorEnableCollision`/`SetCollisionEnabled`/destroy on a blocking volume) and replay it. The log shows nothing for it.
8. **Objective map desync: destroyed bug hole still shows on the client.** Second mission (LOS_ objectives, started t=1711066). The host blew up a bug hole; on the client's map it did not show as destroyed. The bug holes are `BP_DestructibleSpawner_Bugnest_HumanGameplay_C_*` (markers for `LOS_O02_SO05a/b`, card 070 sent them).
